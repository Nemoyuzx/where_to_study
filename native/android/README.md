# Android 原生客户端

该目录是唯一的 Android 客户端源码，使用 Kotlin + Android Framework Views，
不依赖 Tauri、WebView 或 Compose。应用包名为 `com.nemoyu.wheretostudy.nativeapp`。

设置页提供默认、海洋蓝、鸢尾紫、暖琥珀、玫瑰和自定义颜色主题。自定义主色、强调色和选中日期支持严格的六位 RGB 输入、即时预览及本地保存；切换预设或恢复默认会保留上次有效自定义颜色。主题独立存储在 `color_theme_preferences`，不触发账号保存或网络刷新。原生控件、日历画布和桌面小组件会即时换色，默认浅色/深色色板和 DDL 语义颜色保持原值。共享规则见 `docs/color-themes.md` 与 `contracts/v1/color-themes.json`。

非默认主题使用柔和预设，并由主色同步生成页面、卡片、浮层、输入框、导航和边框的背景层次；现有自定义主色也会自动影响这些背景，无须额外保存字段。文字会根据实际背景调整明暗，保持可读性。

构建、单元测试和 Lint：

```bash
./scripts/native-android-build.sh
```

账号和密码由 Android Keystore 中的 AES-GCM 密钥加密后存入应用私有
`SharedPreferences`；校区等非敏感偏好直接存储。当前原生版已接入移动教务的个人课表和当天两校区空教室请求，并使用 `AtomicFile` 分别保存本地课表和空教室缓存。课程联动、原有教学楼限制、三位教室号、双门教室号以及日/周/月/年视图均复用 `contracts/v1` 的脱敏夹具测试；应用不再推断或标记考试周。

手机底栏和平板/折叠屏侧栏均按“空教室 → 教学日历 → 查询 → 设置”排列；“查询”是独立一级页面。班车使用固定 HTTPS API，只展示当天生效且通过严格校验的双向班次、下一班与发车地点；重要事件复用教学日历的公开 Contest DDL 和校内通知缓存，支持全文/分类筛选、过期切换、DDL 升序和本地收藏，不包含课程作业或自定义日程。学术会议与期刊专题可通过独立会议开关进入教学日历。

空教室数据仅查询当天；应用启动时会在已有凭据且当天缓存缺失时刷新一次，并通过 Android `JobScheduler` 在每天北京时间约 07:00、网络可用时自动刷新。该任务是一次性 persisted job，每次完成后安排下一天，设备重启后由系统恢复，不使用常驻轮询。教学日历支持缓存法定节假日、日/周/月/年视图、按课程数量加深的年视图色块和日/周当前时间线。节假日运行时数据通过固定版本的 unpkg HTTPS 年度 JSON 地址获取，来源归属和许可证边界见根目录 README。教学日历可在用户授权后，将本地缓存课表展开到 `Asia/Shanghai` 的实际上课日期并写入主可写系统日历；应用使用稳定标识更新已有事件，重复导入不会产生重复日程。

应用提供可调整尺寸的原生“今日课程”桌面小组件，直接读取应用私有课表缓存，展示日期、星期、教学周、当前或下一节状态、时间、节次、教室与教师。Android 12 及以上按启动器提供的实际尺寸生成布局，旧版按横竖屏尺寸适配；在实际容量和用户课程上限内优先显示今日课程，剩余行补充带“明日”标识的课程，总数最多 6 门。容量按系统字体和中英混排的实际行高计算，110dp 最小高度及大字体下优先保留课程标题，空间不足时收起日期、计数或详情，完整已展示课程详情仍提供给无障碍朗读。明日课程按明日日期和教学周计算，不参与今日当前或下一节状态。今日无课但明日有课时显示明日课程，两日都无课时显示“今日无课”。设置预览使用虚构的今日及明日课程，与真实小组件共用尺寸、行选择和标题逻辑。课表刷新、账号清除、日期或时区变化以及应用更新后会重绘，另有北京时间午夜的非精确定时重绘与系统定期刷新，均不新增网络请求。广播通过 `goAsync` 把本地读取移至后台，设置 8 秒超时保护，并保证 `PendingResult` 只结束一次；一次批量刷新只读取一次课表，各组件共享结果。

每日课程摘要默认关闭，提醒时间默认北京时间 07:30。设置支持双语 24 小时时分选择，保存为 `daily_course_notification_minutes`（0–1439，默认 450）；旧配置、非法存储值及清除本地数据均回到默认时间。修改时间会立即使旧执行版本失效并重排已开启的提醒。持久化 `JobScheduler` 约在所选时间运行，系统节电可能造成延迟；有效投递窗口为所选时间后的 30 分钟，并在北京时间当天结束时截断，不使用精确闹钟。后台任务携带计划时间、分钟值及持久化版本，投递前再次验证；记录已发送的北京时间日期，改时或重试不会让当天重复通知。关闭提醒、权限撤销、账号切换或清除本地数据会撤销旧任务，且没有可用 Keystore 凭据时不会继续安排后台刷新。

打开应用、重启和日期变化会保留仍匹配的有效计划；当天未发送且仍在有效窗口内时恢复当天任务。系统暂时停止任务会在有效窗口内重试，过窗则续排下一天，用户停止或失效计划不会被重新授权。修改系统时间会重新计算等待时长。23:59 的投递和调度期限均在当日结束截断，系统延迟仍可能使当天无法投递。AAB 关闭语言资源拆分，应用内中英切换不依赖额外下载。

生成经过测试和签名校验的通用 APK 与 Play 发布 AAB：

```bash
./scripts/native-android-signing-init.sh
./scripts/native-android-package.sh vX.Y.Z
```

签名初始化脚本将本地 keystore 和 `keystore.properties` 写入已忽略的 `native/android/keystore/` 与 `native/android/keystore.properties`。打包脚本优先从 `ANDROID_SIGNING_*` 环境变量读取签名配置，未设置时使用上述本地配置。脚本运行 Release 单元测试与 Lint，验证 APK 签名和 ZIP 对齐，并验证 AAB 的 JAR 签名与 ZIP 完整性。APK、AAB 及各自 SHA-256 文件会写入 `release-artifacts/`，签名文件和密码不会进入仓库或安装包目录。APK/AAB 还会携带并逐字节校验根 `LICENSE`、`THIRD_PARTY_LICENSES.html` 与 `THIRD_PARTY_NOTICES.md`。公开 GitHub Release 只上传 Universal APK；AAB 仅保留给应用商店或内部交付，`.sha256` 只用于发布核验。
