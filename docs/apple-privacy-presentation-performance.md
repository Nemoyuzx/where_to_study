# Apple 隐私页呈现优化（0.3.2 源码）

用户报告点击隐私说明后稍有延迟。本轮只优化呈现与布局，不修改政策、同意／拒绝流程、声明日期或版本，不调整字号、间距或关闭系统动画。设置的两个入口和首次启动授权页使用同一个呈现实现。

## 源码发现与修改

- 隐私页是本地内置文字，点击链没有网络、文件读取、Markdown 解析或人为等待。原 `ScrollView/VStack` 同步建立十段双语长文，逐段测量完整高度，设置根状态切换还会使包含课程小组件预览的设置布局更新。
- 改为 `LazyVStack` 和独立 `PrivacyPolicySection`，连长文排版与主题解析也按可见段落进行。完整内容与末尾 GitHub 链接仍可滚动抵达，不使用空白占位或延迟填充正文。
- 稳定设置／授权页以 `@State` 持有旧式 `ObservableObject` 引用，但不订阅其发布；仅小型 `PrivacyPolicyPresentationHost` 使用 `@ObservedObject`。按钮不持有弹窗状态，避免单双列切换销毁按钮时丢失弹窗；弹窗锚点保持在稳定屏幕根部。
- 入口的按钮样式不传入弹窗；保留原生“完成”与系统呈现动画。已无焦点时不重复写入 `FocusState`。不增加后台任务、定时器、文档缓存或网络请求。

十段正文与修改前完全一致，内容／标题序列的 SHA-256 为 `a5c5876f35c1952b2642862577107a028207fa131a817035e4441c648c229aee`；生效日期仍为 2026-10-02，Consent 版本仍为 1。

## 应用内时序对照

2026-10-03，本机 iPhone 16e / iOS 26.3.1 模拟器、Xcode SDK 26.5、相同示例依赖。DEBUG 显式 `--ui-test-privacy-presentation` 才启用单个单调时钟和 UIKit 生命周期探针；不保存／上传信息，不用 XCTest 等待耗时当作应用时序。Calendar 原探针默认行为保留。首次指同一次应用启动后的第一次打开，不指全新系统或真实手机首次安装。

下表是按钮动作至隐私内容控制器 `viewWillAppear` 的准备时间，不是 GPU 首帧或帧率测量：

| 入口与主题 | 首次：修改前 → 后 | 再次：修改前 → 后 |
| --- | --- | --- |
| 设置／默认 | 140 → 53 ms | 114 → 26 ms |
| 设置／玫瑰 | 137 → 52 ms | 116 → 27 ms |
| 首次授权页 | 210 → 80 ms | 120 → 26 ms |

原生协调器均报告动画开启、时长 400ms，没有通过禁用动画取得改善。到 `viewDidAppear` 的完整时间分别为设置默认首次 855→756ms、玫瑰首次 887→791ms、授权页首次 968→654ms；完整呈现包含正常动画及生命周期调度，不能声称瞬时打开。数据是每场景一次前后测量，不是统计性能基准或真机保证。
