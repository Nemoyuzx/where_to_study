# Code of Conduct

## Our standard

Project participation must remain professional, technically relevant, and
respectful. Contributors and maintainers are expected to:

- discuss behavior and evidence rather than attacking people;
- give reproducible context for technical claims and acknowledge uncertainty;
- accept review, correction, and disagreement without harassment;
- protect credentials, personal data, unpublished vulnerabilities, and private
  communications;
- respect copyright, licenses, trademarks, and third-party service rules;
- avoid spam, manipulation, impersonation, threats, sexualized conduct, and
  discriminatory or demeaning language.

## Scope

This standard applies to repository issues, pull requests, discussions, code
review, release coordination, and other project spaces. It also applies when a
person is clearly representing the project in a public forum.

## Reporting conduct concerns

For an issue that can be handled safely in public, use GitHub's content-reporting
tools or flag the relevant comment for a maintainer. Do not escalate by reposting
abusive material.

The project currently publishes no confidential conduct-reporting address. For
a sensitive concern, open a
[Conduct contact request](https://github.com/Nemoyuzx/where_to_study/issues/new?template=conduct_contact.yml)
containing no names, allegations, screenshots, or personal details. A maintainer
can arrange a private channel before receiving the report. This limitation is
stated explicitly so contributors are not directed to a fictional contact.

No acknowledgement or resolution SLA is promised. Anyone handling a report
should limit access to people needed for review, disclose conflicts of interest,
and avoid retaliation.

## Enforcement

Maintainers may edit or remove content, close or lock threads, reject changes,
or restrict participation when needed to protect the project and its
participants. Decisions should consider context, severity, repeated behavior,
and whether the person corrected the issue. Possible actions range from a
private correction or warning to temporary restrictions or a permanent ban.

Project moderation does not replace GitHub's platform enforcement or applicable
law. Immediate threats or unlawful conduct should be reported to the appropriate
platform or authority rather than investigated through a repository issue.

## License and contribution status

The repository currently has no `LICENSE`, Contributor License Agreement, or
Developer Certificate of Origin. It must not be represented as OSI-licensed open
source until maintainers select and publish a license. Submitting a pull request
does not itself select a project license. Contributors must have the right to
submit every code, asset, data file, and dependency change they propose, and
maintainers must not assume rights beyond applicable terms and explicit grants.
