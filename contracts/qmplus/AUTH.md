# QMplus 官方网页登录辅助契约（0.4.0 源码）

`qmplus-auth.js` 与只读业务同步脚本 `qmplus-sync.js` 完全分开。native 仅在用户已明确保存独立 QMplus/Microsoft 账号密码、开启匹配的本机授权，且当前 ArkWeb/WKWebView/WebView 是官方**主文档**时安装此脚本。安装必须返回固定 `AUTH_INSTALLED`；已有同名全局返回 `AUTH_CONFLICT`，不得向它发送凭据。脚本不发送网络请求、不读 Cookie/Storage，不注册可被网页主动调用的 native 密码桥。

`qmplus-page.js` 是独立的只读主文档分类器，只返回 `loading / guest / authenticated / error / unknown`，不创建消息桥、不读取输入、存储或会话键。只有经过当前 owner／文档的已登录证明，原生同步入口才可用。明确的 Moodle fatal-error 标记或异常对话框优先于菜单；普通课程提醒不是 fatal-error。手机首页可能没有 `notloggedin` class，仅当 `page-site-index`、无菜单和安全的同源 SAML 链接共同存在时才补判访客。共享同步脚本在读取会话键和每个业务请求之前重复验证，HTTP 200 的错误／欢迎详情不能误标为已获取。

已确认的用户菜单可能先于 Moodle 会话配置挂载。`qmplus-sync.js` 在每次 AJAX 前只读确认 `M.cfg.sesskey` 已是非空字符串；缺少配置时在同一次同步内累计最多等待 20 次、每次至多 250 毫秒，不发空键请求。等待共享原有单飞、取消与 120 秒总期限，不重置总计时；期间变成 guest／error／外域立即停止。仅明确 guest 返回 `QM_LOGIN_REQUIRED`；已登录但配置耗尽等待、loading 或 unknown 返回固定 `QM_PAGE_NOT_READY`。后者是重试同步的状态，消费端须保留会话及上次业务缓存，不转换成登录恢复或删除授权。

重连从固定 Dashboard 发起新的 GET 并重新证明状态，不重用旧 DOM 作为有效会话证明。官方登录入口仅接受精确站点／允许路径和已核验链接，重复页首／页尾链接指向同一安全目的地不构成多个身份。登录回跳 POST 保留原请求与 WebKit 配置；网页自行关闭不代表认证完成，不可因此打断父窗口的原始回跳。不自动重放验证码、密码或 SAML ACS POST，也不自动删除账号或 Cookie 来恢复错误。

Apple 默认连接先在后台核查 Dashboard；已确认的访客页自动进入普通 Login，再进入已核验 SSO。普通 GET 与密码填写授权分离，Login 和 SSO 各有独立的有限预算；未保存密码也能尝试复用官方会话，但不能据此读取或填写密码。发出自动 GET 前同步撤销旧 document 的回调资格，保留本次凭据步骤预算。已解析出的明确访客标记可提前识别；入口尚未解析时有限等待 DOM，已认证判定仍等待页面就绪。已确认的访客欢迎页在预算耗尽后保留缓存并提示重试，不要求用户手动点击 Login。只读同步明确返回 `QM_LOGIN_REQUIRED` 时，且本次尚未进入 Login、尚未选择账号或提交凭据，可进行一次登录恢复和一次后续自动同步；这不会重建凭据 ledger。

Apple 116 将已核验官方登录链中的有限布局暂停与撤销连接分开：仅原 owner、原凭据版本、仍有效授权，并且新的真实导航已 `didCommit` 后，允许恢复一次尚未消耗的阶段。真实导航身份必须与当前 active navigation 一致且不同于暂停导航；同页 history、前台恢复制造的 epoch、旧回调不能恢复。所有已 claim 的阶段和真实 ACK 保留，既不重选已选账户也不重放密码；再次暂停后需显式开始新连接。手动打开原页不重置 ledger，只有后续真实提交 ACK 才自动收起人工窗口。外域、协议异常、明确 HTTP／网页／WebKit 错误、账号不匹配、授权变化、辅助脚本冲突和未知表单干扰走不可恢复的 stop；验证码／MFA 仍由用户完成。此恢复机制未改变凭据路径和精确身份校验，不宣称修改官方会话有效期。

凭据页面白名单仅包括 `https://qmplus.qmul.ac.uk` 的已登录用户菜单，以及 `https://login.microsoftonline.com/569df091-b013-40e3-86ee-bd9cb9e25814/saml2` 或同租户 `/login`。Microsoft 凭据表单须唯一为 `form#i0281`，提交目标仍是同源同租户 `/login`；账号是可见 `input#i0116[name=loginfmt][type=email]`，普通下一步是可见 `input#idSIButton9[type=submit]`。密码阶段账号框已移除，可见 `input#i0118[name=passwd][type=password]`，`#displayName` 仅在网页内部与本机授权账号比对。预加载的 10×13、透明度 0 密码框**不是**可填写密码页。新增的精确路径 `https://login.microsoftonline.com/kmsi` 仅可识别验证挑战或继续保持登录，不能填写账号或密码。

实际模拟器的非敏感主文档路由与结构元数据已确认，MFA 方式选择页可位于 `https://login.microsoftonline.com/common/DeviceAuthTls/reprocess`，包含官方 MFA 标题节点。该地址单独归类为 **verification-only**：仅此完整路径忽略大小写，不接受尾斜杠、编码替换、相邻路径或其它域名；native 不为它读取保存账号／密码，仅调用 `inspect(nonce, '')`。有效当前文档中只做 `challenge` 识别，标题尚未挂载或没有明确挑战时返回 `loading`／`LOADING` 使用原有有限原生等待预算；不会进入账号选择、用户名、密码或 KMSI 继续分支，任何对应 `fillAndSubmit` 请求均被拒绝。验证路径许可与凭据提交许可必须分别维护。

默认连接的普通账号选择、账号输入、密码提交、已识别的 Stay signed in 确认及成功回跳连续在后台进行。只有明确识别出的验证码／MFA 返回 `challenge` 才自动显示官方窗口；挑战本身由用户完成，helper 不读取验证码、不点击验证按钮。其它域名、路径、frame、未匹配的账号选择、未知表单、权限、风险、条款及错误继续返回 `manual`；自动流程停止并保留显式打开官方网页的入口，不把这些状态当作验证码而自动弹窗。首次布局／未知页面仍受原有有限等待、后台撤销、错误和超时预算约束。

1. native 为每次真实 document 生成非敏感 nonce，并维护 presentation/document epoch、每阶段一次提交的本机 ledger。helper 在本次 document 内还绑定首次检查时的完整地址，地址变化即拒绝，地址本身永不返回。页面调用 `WTSQmAuth.inspect(nonce, accountHint?, identityAcknowledged=false)`，只接收固定 `{v:1,stage,document,accountMatch,reason}`；不会收到网址、账号、输入值、HTML 或令牌。`identityAcknowledged` 只接受布尔值 `true`，不能从检查结果反推，且一次 inspect 不会把该参数保存为后续调用的授权。
2. 仅当状态是明确的 `username`，才允许 `fillAndSubmit({document,stage:'username',account})`。不能同时传密码；辅助脚本在点击普通 Next 前再次校验官方主文档、nonce、表单、可见且无遮挡的唯一控件。
3. 已核验的账号选择页须有唯一 `#tilesHolder`；只接受可见 `div.table[role=button][data-test-id]` 中唯一、精确匹配已授权完整账号的条目，并保留唯一 `.table-cell.text-left.content`。内容格只含完整邮箱时直接精确比对；同时展示姓名／状态时，最多检查 128 个后代元素，只接受其中唯一可见、包含完整邮箱的叶节点且该邮箱精确匹配，绝不截取子串。邮箱区域的命中点须仍位于条目内，最近的交互祖先必须是该条目而非溢出菜单、链接或另一账户；实际只点击已核验条目。若官方 `data-test-asynctilesloaded` 明确为 `false`，或已有唯一完整账号匹配但布局／命中尚未就绪，只返回 `loading`／`LOADING` 使用原生有限等待预算，不消耗选择次数或点击任何控件。错账号、歧义、禁用、其它输入框或验证控件仍拒绝；遮挡和溢出菜单命中在等待期间也不会点击。`account` 阶段调用只携带账号和 nonce，不携带密码；点击前先消耗本机尝试额度，`ACCOUNT_SELECTED` ACK 单独记录，不伪装为账号输入提交成功。
4. 密码只在本 helper 已提交或已选择匹配账号，或者 native 传入当前连接的独立身份 ACK 时填写。跨真实 document 的 ACK 必须来自同一 connection owner、同一保存凭据版本，且已消耗的账号步骤实际返回 `ACCOUNT_SELECTED`／`USERNAME_SUBMITTED`；不能凭“尝试过”、新网页自称成功或其它连接的回调建立。官方 Cookie 也可能直接进入密码页：只有完整通过表单、动作、唯一可见密码框、唯一无遮挡 `#displayName` 与所存账号精确匹配、无其它确认控件且密码未尝试的页面，才会在无历史 ACK 时返回 `password`／`CURRENT_ACCOUNT_VERIFIED`。native 可在当前 owner、document、凭据版本仍一致时确认这个当前账号并记录独立 ACK，不伪装为提交过用户名。native 当前授权、前台状态和 ledger 都许可后，调用 `fillAndSubmit({document,stage:'password',account,password,identityAcknowledged:true})`。同文档账号提交／选择 ACK 可省略该布尔参数；inspect 不会自行保存当前账号确认。helper 在填写前仍完整重验当前 `#displayName` 和表单，最多点击一次普通 Sign in；任何失败均固定码、**不自动重试**。账号选择、输入和密码各自保留整次连接的尝试额度，导航不重置。
5. `continue` 只代表已核验的 KMSI，而不是泛指 Next／Accept：须同时存在可见唯一 `#kmsiTitle` 且标题明确表示保持登录、`form#i0281`、可点击唯一 `input#idSIButton9[type=submit]` 和 `input#idBtn_Back[type=button]`，表单提交目标精确为同源 `/kmsi`，账号／密码字段已移除、`#displayName` 精确匹配，且身份 ACK 仍有效。缺少账号提示返回 `ACCOUNT_HINT_REQUIRED`，身份标记缺失／不可见／尚非完整账号返回 `KNOWN_FORM_ABSENT`，均不允许自动继续，也不能据此宣称账号不同；只有可见完整账号确实不匹配才返回 `ACCOUNT_MISMATCH`。官方 Cookie／用户完成 MFA 后可能直接进入此页；全部严格条件通过但无历史 ACK 时，同样返回 `continue`／`CURRENT_ACCOUNT_VERIFIED`，native 仅在当前 owner、document、凭据版本仍有效时确认当前账号，再调用 `fillAndSubmit({document,stage:'continue',account,identityAcknowledged:true})`。只能返回 `CONTINUE_SUBMITTED` 或固定拒绝码，绝不接收密码。该阶段有独立的整次连接一次预算。仅点击表示保持登录的 Yes；可选的“不再显示”复选框保持原值，只有已知控件且关联可见 label 明确表示这一显示偏好时才容忍它存在。未知复选框、按钮、警告、弹窗或表单动作一律不自动确认。
6. `challenge` 只使用固定原因 `CAPTCHA_REQUIRED`／`MFA_REQUIRED`，`accountMatch` 固定为 `false`，不返回提示文本或输入内容。只读识别依据是可见控件的明确 CAPTCHA 可访问标签、一次性验证码输入语义，或明确的 Authenticator 登录批准标题；已确认的 MFA 方式选择页匹配可见 `h1`／`h2`／`role=heading` 或唯一可见的官方 `#idDiv_SAOTCS_Title`，仍须完整标题为 `Verify your identity`、`验证您的身份` 或对应繁体文字。此识别只请求用户操作，不选择短信／电话等方式、不发送验证码。明确可见的挑战可在其它资源仍加载时报告；普通凭据与 KMSI 仍等待文档就绪。隐藏预加载控件、普通未知输入和通用错误提示不算挑战。识别不完整的改版／语言继续按 `manual` 处理，用户仍可主动打开官方页。native 在挑战期间只读观察官方导航／页面变化并保留原 ledger；验证完成后只恢复尚未消耗的已核验阶段，不重放密码或验证请求。

两方法只返回固定状态/原因码；密码只作为本次官方页填写调用的入参，不进入 inspect 结果、业务快照、日志、剪贴板、截图、Widget 或第三方服务。应用关闭自动填写/退出/清本地数据时撤销本机授权并清除独立安全存储；操作系统自己的密码管理器由用户另行控制。三端接线前须保持同一 canonical 脚本字节，按各端实际页面生命周期逐项验收；假 DOM 测试不能冒充真实 Microsoft MFA 成功。

保存编辑开关首用预选开启，用户明确关闭的非秘密偏好持久保留；预选本身不会读取密码、保存资料或建立自动填写授权。只有明确点击保存且安全记录与授权校验成功后，才显示持续的“已保存”状态并允许使用。清空编辑框不代表已删除安全记录，保存的密码不会回显；删除登录资料与恢复初始编辑偏好是独立操作。

共享合成 DOM 测试入口：`node --test test/qmplus-auth.test.js`。Apple 114 初始实现阶段按用户要求只补充测试源；随后用户明确授权本机验证账号选择问题，本次限定修复的 37 项认证规格已通过，包含带姓名／邮箱／状态的嵌套条目及独立菜单命中、异步条目与精确匹配条目布局等待、跨 document ACK、固定挑战分类、验证专用路径不能填写或提交、KMSI 独立一次提交及未知确认拒绝。同步就绪等待另由 `test/qmplus-protocol.test.js` 与 `test/qmplus-page.test.js` 覆盖。合成规格不读取真实凭据，不能据此声称已验证当前租户或截图对应设备的全部真实 SSO 分支。

首次布局允许有限等待，但不放宽 URL、表单或提交次数。实际 Microsoft 页面会用同一 `placeholderContainer` 内的 `placeholderInnerContainer > .placeholder[aria-hidden=true]` 覆盖空输入框；只把这一已核验的提示结构视作该字段的点击区域，并再次验证文档、控件身份、可编辑性、尺寸及其它确认控件。任意其它遮罩、隐藏预加载密码框或未知控件仍拒绝自动填写。隐藏窗口无法完成布局时仅有限等待，耗尽后保留手动入口，不以布局失败为理由自动显示；不保证所有系统／登录分支都能后台完成。

Tauri 的本机提交 ledger 属于一次连接展示，跨导航保留账号选择／输入／密码／继续阶段的已尝试记录和同 owner、同凭据版本的真实身份 ACK；每个文档仅更换 nonce 与地址。隐藏窗布局继续有限等待，原有静默流程总时限保留；等待期间不为普通布局或表单状态自动显示。只有明确 `challenge` 可显窗并只读等待用户完成。超时、明确手动步骤、授权撤销、应用后台或关闭窗口会停止自动填写并清理轮询计时器。窗口之间切换不视为应用后台；macOS 还核对应用激活状态，以保留 Inspector 和系统对话框。此取消不删除已验证业务快照，也不关闭供用户完成 MFA 的官方页面。默认连接在已验证身份开始只读同步时自动收起，保留本次 owner 和请求，结果发布后自动返回；用户明确打开的官方课程或活动页仍保留。

KMSI 结构依据为 Microsoft 官方 MSAL 仓库提交 `5c78da100bf526d4510cbd6b56f1373100afd4b4` 的 [`Constants.ts`](https://github.com/AzureAD/microsoft-authentication-library-for-js/blob/5c78da100bf526d4510cbd6b56f1373100afd4b4/samples/e2eTestUtils/src/Constants.ts)（`KMSI_PAGE` 与一次性代码输入选择器）及 [`KmsiTestUtils.ts`](https://github.com/AzureAD/microsoft-authentication-library-for-js/blob/5c78da100bf526d4510cbd6b56f1373100afd4b4/samples/e2eTestUtils/src/KmsiTestUtils.ts)（Yes／No 的独立选择器及会话持久化含义）；官方 [Partner Center 示例](https://learn.microsoft.com/en-us/partner-center/developer/enable-secure-app-model) 记录了 `/kmsi` 回跳页。上述为本次静态参考，不代表已使用实际凭据验证当前 QMUL 页面；运行时必须同时满足更窄的结构与身份条件，任何未覆盖形状保守退出。

MFA 方式选择页的标题 ID 依据为 Microsoft 官方 MSAL common-for-android 提交 `f0aa6a9c55575e26380d526ab97126b2cb2e5e01` 的 [`AadLoginComponentHandler.handleVerifyYourIdentity`](https://github.com/AzureAD/microsoft-authentication-library-common-for-android/blob/f0aa6a9c55575e26380d526ab97126b2cb2e5e01/uiautomationutilities/src/main/java/com/microsoft/identity/client/ui/automation/interaction/microsoftsts/AadLoginComponentHandler.java#L319)。这里只复用只读标题定位，不复用其测试代码中的验证方式选择，不推断未核验的 Proofs 容器或放宽 URL／凭据路径。

“启用 QMplus”是功能开关，和“关闭自动填写并删除登录信息”不同。关闭功能只撤销当前 owner、停止后续同步、隐藏课程区域；保留独立安全记录、授权、会话和上次快照。关闭期间及重新启用后的旧回调均不能重新发布。新用户默认关闭，既有授权元数据可迁移为开启，明确的关闭记录优先；不读密码来决定默认值。
